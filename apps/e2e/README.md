# E2E

Интеграционные тесты полного пути лида: HTTP-запрос в gateway => валидация => BullMQ (redis) => обработка в router =>
доставка delivery-адаптерами => контроль доставки

## Запуск

```bash
pnpm test:e2e # из корня монорепы
```

Требуется запущенный Docker (testcontainers поднимает postgres и redis сам, на случайных портах, и удаляет их после
прогона).

## Как это работает

- **Инфраструктура**: testcontainers стартует реальные `postgres:18-alpine` и `redis:8-alpine`; призма-миграции
  применяются `prisma migrate deploy` к тестовой базе.
- **Приложения in-process**: gateway запускается как HTTP-приложение на случайном локальном порту; supertest
  отправляет запросы через `app.getHttpServer()`. Сервер остаётся открытым для параллельных запросов до конца прогона.
  Router запускается как application context. BullMQ связывает приложения через тестовый Redis.
- **Контроль доставки**:
  - database — реальная запись, проверяется запросом через `PrismaService`;
  - http — `HTTP_LEAD_DELIVERY_ENDPOINTS` указывает на локальный sink-сервер, который записывает всё присланное;
  - console — шпион за `Logger.prototype`;
  - telegram — вызовы Bot API перехватываются подменой `globalThis.fetch` (синк), при этом работают реальный клиент и
    транспорт; отдельный тест проверяет пропуск выключенного канала (spy на геттер `enabled` адаптера);
  - email — локальный SMTP-сервер (sink), письма парсятся через `mailparser`.
- **Асинхронность**: результаты обработки задач проверяются периодически (`waitFor`).
- **Структура тестов**: тяжёлый setup (контейнеры, миграции, приложения) один в `beforeAll`; дальше отдельные группы —
  gateway, каждый адаптер, выключенные каналы. Каждый тест шлёт свой лид с уникальным `contact` и фильтрует эффекты по
  нему: gateway отправляет каждый лид во все каналы, и без маркера тесты мешали бы друг другу.

## Технические детали

- `NODE_OPTIONS=--experimental-vm-modules` — Nest 12 поставляется как ESM, а jest требует этот флаг для `require(esm)` в
  CJS-рантайме тестов.
- e2e объявляет `@nestjs/common`, `@nestjs/core`, `@nestjs/swagger` и их peer-зависимости с теми же точными версиями,
  что у gateway и router: pnpm схлопывает их в один экземпляр. Две копии Nest в процессе сломали бы DI и
  instanceof-проверки, поэтому тест `shares one Nest instance with gateway and router` проверяет, что gateway и router
  разрешают те же пакеты, что и e2e. При обновлении Nest версии нужно менять во всех трёх `package.json`.
